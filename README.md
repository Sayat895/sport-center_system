# 🏋️ SportClub — онлайн-запись в спортивный центр

SportClub — адаптивное приложение для просмотра расписания, записи на занятия и управления спортивным центром. Клиенту доступны пять направлений, личный кабинет и уведомления. Администратор управляет клиентами и записями, добавляет занятия и выгружает отчет.

## 🧩 Из чего состоит проект

| Контейнер | Назначение |
| --- | --- |
| `db` | PostgreSQL 15 — пользователи, тренеры, расписание и бронирования; данные сохраняются в Docker volume. |
| `redis` | Redis 7 — кэш расписания и CSV-отчета. |
| `backend` | Python 3.11 + FastAPI — асинхронный API, JWT, проверка ролей, правила записи, создание тестовых данных и отчеты. |
| `frontend` | React + Vite + Tailwind CSS — интерфейс клиента и администратора; Nginx раздает SPA и проксирует `/api` в backend. |

## 🚀 Запуск

Нужны Docker Desktop и Docker Compose. В корне проекта выполните:

```bash
docker compose up --build
```

Для локальной демонстрации дополнительных настроек не требуется. Чтобы включить вход и регистрацию клиентов через Google, создайте OAuth Client ID типа **Web application** в Google Cloud Console и добавьте `http://localhost:3000` в список разрешенных JavaScript origins. Этот вариант использует Google Identity Services Token Client в режиме popup и не требует Authorized redirect URI. Создайте `.env` на основе `.env.example`, укажите `GOOGLE_CLIENT_ID` (значение с окончанием `.apps.googleusercontent.com`), а также задайте `POSTGRES_PASSWORD` и длинный случайный `JWT_SECRET`; затем запустите `docker compose up --build`. Для другого домена добавьте его в разрешенные origins OAuth-клиента. Бэкенд проверяет access token у Google, сверяет, что он выдан этому Client ID, и получает подтвержденный email через UserInfo. При первом входе клиентский аккаунт создается автоматически. Google не может войти в админ-панель.

Демо-вход по email работает и без Google OAuth. Если `GOOGLE_CLIENT_ID` не настроен, окно входа покажет подсказку по настройке.

- 🌐 Приложение: [http://localhost:3000](http://localhost:3000)
- 📘 Swagger API: [http://localhost:8000/docs](http://localhost:8000/docs)
- 💚 Проверка сервиса: [http://localhost:8000/api/health](http://localhost:8000/api/health)

Сервисы настроены на автоматический перезапуск. При первом запуске backend создает таблицы и заполняет пустую базу. Для остановки нажмите `Ctrl+C`; чтобы остановить контейнеры в фоне — `docker compose down`. Данные PostgreSQL и Redis хранятся в Docker volumes.

## 🔑 Демо-доступ

| Роль | Email | Пароль |
| --- | --- | --- |
| Администратор | `admin@sport.kz` | `Admin123!` |
| Клиент | `client@sport.kz` | `Client123!` |

На форме входа также есть кнопки быстрого входа для обеих ролей. В базе создаются еще 12 демонстрационных клиентов `member1@sport.kz` — `member12@sport.kz`; пароль каждого — `Client123!`.

## 👆 Куда нажимать для проверки всех 12 пунктов

1. **Простое расписание.** Откройте сайт — занятия показаны на главном экране по дням. Фильтры над карточками переключают тренажерный зал, бассейн, бокс, йогу и кроссфит.
2. **Запись за пару нажатий.** Нажмите «Войти как клиент», затем «Записаться» на карточке. Статус кнопки и счетчик мест обновятся. Повторная запись и переполненная группа отклоняются с понятным сообщением.
3. **Спортивный интерфейс.** Проверьте темную тему, лаймовые и синие акценты, карточки с уровнем нагрузки и заполненностью; ширина интерфейса адаптируется к экрану телефона.
4. **Работоспособность и проверка API.** Откройте `/api/health`: ответ `{"status":"ok"}` означает, что приложение отвечает, а PostgreSQL и Redis доступны. В `/docs` можно посмотреть методы API.
5. **Администрирование.** Войдите как администратор и откройте «Админ-панель». В таблице пользователей измените ФИО, телефон, абонемент или роль. Здесь же можно добавить тренировку и отменить активную запись клиента.
6. **Защита данных.** Попробуйте войти с неверным паролем — сервер его отклонит. Пароли в базе сохраняются в виде bcrypt-хэшей; формы и API валидируют данные, а запросы администратора защищены ролью.
7. **Кэш и база.** Откройте расписание, затем обновите его: API использует Redis-кэш. PostgreSQL хранит записи и индексы для поиска по расписанию и пользователям.
8. **Разные устройства.** Уменьшите ширину окна браузера или откройте сайт на телефоне: карточки, фильтры, меню и формы перестраиваются под узкий экран.
9. **Уведомления.** Как администратор, отмените клиентскую запись внизу админ-панели. Клиент увидит всплывающее сообщение после действия и постоянное уведомление в разделе «Мой кабинет».
10. **Структура и качество.** Backend расположен в `backend/`, интерфейс и конфигурация сборки — в `frontend/`; каждый сервис собирается в отдельный контейнер.
11. **Безопасный вход и роли.** Выйдите из аккаунта и попробуйте демо-вход администратора, затем клиента. Админ-панель доступна только роли `admin`; API использует подписанные JWT-токены.
12. **Отчет.** В админ-панели нажмите «Посмотреть отчет»: откроется форматированная сводка с таблицами по тренерам, направлениям и каждому занятию, включая свободные места. Кнопка «Скачать Excel» выгружает оформленную книгу с отдельными листами и фильтруемыми таблицами; «CSV» скачивает совместимый с русской локалью файл с разделителем `;`.

## 🗂️ Данные при первом запуске

В пустой базе автоматически создаются администратор, демо-клиент, 12 клиентов с тестовыми абонементами, пять тренеров, 15 занятий на ближайшие семь дней и начальные записи клиентов. Все тестовые клиенты используют пароль `Client123!`.
